# Права доступа пользователя

Роль задаёт начальные права. Индивидуальные настройки изменяют отдельные права сотрудника и сохраняются при смене роли до явного сброса.

## Планирование

«Просмотр» разрешает видеть записи. «Управление» объединяет создание, изменение и удаление, но сервер проверяет каждое действие отдельно. «Разные права» означает, что эти действия были настроены по-разному: они сохраняются до выбора нового общего условия.

Просмотр проекта открывает все его процессы, задачи, подзадачи, вехи и назначения ресурсов. Просмотр процесса открывает его содержимое; просмотр задачи — её подзадачи и назначения. Запрет ниже не отменяет доступ через родителя. Заблокированные кнопки объясняют это при наведении. «Только через родителя» убирает отдельное разрешение, сохраняя доступ через родителя. Для управления такого наследования нет.

«В проектах сотрудника» проверяет владельца проекта; «В процессах сотрудника» — владельца процесса. Владельцы вложенных записей могут отличаться. «С процессами сотрудника» открывает проект, если внутри есть процесс этого сотрудника, и затем весь проект доступен для просмотра. Владения одной задачей для этого условия недостаточно. Выбранные условия складываются: достаточно любого. Ранее сохранённые сложные условия действуют до явной замены.

Приоритет проекта настраивается отдельно и не разрешает менять другие поля. У назначаемого ресурса и процесса всегда должен совпадать владелец, даже для администратора.

## Сотрудники, табель и ресурсы

- **Сотрудники и табель** — кто виден в списке сотрудников и чьи дни присутствия и отсутствия можно менять. «Свои» здесь означает непосредственных подчинённых, а не собственную учётную запись.
- **Виды дней табеля** — использование обозначений рабочего дня, отпуска, болезни и других состояний дня. Это не статусы задач. Доступ к справочнику не разрешает менять табель сотрудников.
- **Ресурсы для планирования** — состав сотрудников, назначаемый на задачи и используемый для расчёта загрузки. «Свои» означает ресурсы, владельцем которых является сотрудник. Управление ресурсом и назначение ресурса на задачу — разные права.
- **Выбор сотрудников в формах** — список кандидатов для владельца, ответственного и других полей. Не открывает учётные записи, табель и структуру компании.

## Администрирование

Все возможности собраны в одной карточке, но разрешаются независимо:

- **Просмотр учётных записей** — список пользователей, их данные и роли. Без изменения записей и паролей; не открывает табель.
- **Управление учётными записями** — создание, изменение, сброс паролей и удаление. Для работы через страницу нужен также просмотр. Назначать роли может только администратор.
- **Роли и права доступа** — полная настройка ролей и индивидуальных прав, включая собственные. Это административное полномочие, а не режим «только чтение». Оно также открывает профили, необходимые для настройки прав. Само по себе не разрешает сбрасывать пароли или менять шаблон проекта.
- **Шаблон нового проекта** — просмотр и изменение процессов и задач, которые автоматически появляются в новом проекте. Не разрешает настройку ролей. Старое право только на чтение сохраняется: форма недоступна для изменения, пока явно не разрешена настройка.
- **Изменение видов дней табеля** — создание, изменение и удаление обозначений дней. Справочник открывается кнопкой «Виды дней» внутри табеля; отдельной страницы нет. Нужен также просмотр видов дней табеля. При наличии только этих административных прав сотрудники и их табель не показываются. Само по себе не разрешает менять дни сотрудников.
- **Просмотр структуры компании** — схема «кто кому подчиняется». Не разрешает менять руководителей, читать логины, пароли или записи табеля. Смена руководителя требует права изменения учётных записей.
- **Просмотр журнала действий** — история действий пользователей; запросы и ответы могут содержать служебные данные. Не предоставляет других административных прав.

Для новых общих настроек выберите «Доступен» или «Нет доступа». Если сохранены частичные права, «Разные права» показывает каждое действие. Новое общее значение заменяет только действия этой настройки; остальные настройки сохраняются.

## Сохранение

Роль сохраняется сразу. «Сохранить» и «Отменить» относятся к индивидуальным правам. «Вернуть к роли» убирает переопределения одной настройки. «Сбросить индивидуальные» готовит полный возврат к правам роли; затем нажмите «Сохранить». При отказе сервера черновик остаётся доступен.

Администратор всегда имеет полный доступ. Изменение разрешений применяется на сервере; скрытые страницы и кнопки не заменяют серверную проверку.
